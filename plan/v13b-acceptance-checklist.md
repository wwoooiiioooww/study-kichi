# v13-b(かぞく同期) 実機受け入れチェックリスト

前提: index.html の `FIREBASE_CONFIG` に config 貼付済み・Realtime Database ルール設定済み・匿名認証ON。

## 展開手順(必ずこの順)

1. **全端末でバックアップJSONを保存**(パパ・ママモード → 🔧データとシステム)
2. 親端末を最新版に更新 → パパ・ママモード → ☁️かぞく同期 →「同期をはじめる」
3. 子端末を更新 →「つながる」にかぞくコードを入力(初回は合体の確認あり)
4. 1週間は週1バックアップを継続

## チェック項目(2端末A/Bで)

- [ ] ① Aで勉強を記録 → Bに数秒で反映される(ホーム/きろく)
- [ ] ② Bのパパ・ママモードで承認 → Aを開くとスロットカードが出る
- [ ] ③ Aを機内モードにして記録 → 復帰後に自動で合流する
- [ ] ④ Aで券購入(−pt)とBでスロット(+pt)を同時に行う → 両端末の残高が「⭐つうちょう」の合計と一致
- [ ] ⑤ 切断 → 再接続(かぞくコード再入力)でデータが揃う
- [ ] ⑥ 3台目を追加(初回マージ) → 全端末が同じ状態になる
- [ ] ⑦ 写真つき記録: 撮影した端末ではサムネイル表示・他端末では非表示(記録自体は同期)
- [ ] ⑧ 片方でモーダル/作戦入力中に他方が記録 → 入力が壊れない(閉じたとき/タブ移動で反映)
- [ ] ⑨ APIキー・かぞくコードがバックアップJSONと同期データに含まれていない(JSONを開いて確認)
- [ ] ⑩ せってい表示 v14 と sw.js CACHE `studykichi-v14` が一致(配信後、各端末で開き直して更新が届く)

## トラブル時

- 同期セクションが「🔴エラー」→ 電波、FIREBASE_CONFIG、Firebaseコンソールの匿名認証ONを確認して開き直す
- 残高がおかしい → 親の「⭐ポイントちょうせい」で補正(台帳に理由つきで記録される)
- 最悪時 → バックアップJSONから「復元(上書き)」、または「合体(マージ)」で復旧
